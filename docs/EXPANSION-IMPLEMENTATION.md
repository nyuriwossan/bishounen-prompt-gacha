## 1. 何が増えたか

### 1.1 新しい任意の7項目

| 項目 | ID | 詳細な調合のグループ | 候補 | 主な制約（hard） |
|---|---|---|---:|---|
| 年齢の表れ | `ageCue` | 顔・肌・装身具 | 16＋なし | 候補ごとの最低年齢（25／35／45歳〜）。18〜24歳には付かない。若いほど「なし」が出やすい（soft） |
| 髪質 | `hairTexture` | 髪の細部（任意） | 14＋なし | 髪の長さ（巻き毛・コイルは短髪〜）。髪型の質感（直毛／うねり／巻き）と食い違わない |

| 衣装の細部 | `outfitDetail` | 衣装の細部・素材（任意） | 19＋なし | その部位がある服だけ（ネクタイのない服にタイピンは付けない）。同じ部位が既にある服には重ねない。小さな装身具は画角が近いときだけ。コスプレ・拘束・着崩し・衣装の状態の間は重ねない |

- 抽選順（`DRAW_ORDER`）：髪型 → **髪質 → 前髪** → 髪色 …… 髪の配色 → **年齢の表れ** → 衣装 …… ポーズ → 持ち物 → **視線 → 頭の向き** → 背景 …… 衣装の状態 → **衣装の細部 → 素材**。後ろに置くことで、既存の項目の抽選結果（乱数の消費）は増築前と変わらない。
- スイッチは項目ごとのモジュール（`ageCueEnabled` など7つ）。視線・頭の向きは「ポーズ・アングルを出力する」の子（`MODULE_PARENT`）。
- 固定・サイコロ・手で選ぶ・この中から引く・辞書・抽選設定（除外・項目のOFFはモジュールと共有）は、既存の項目と同じ仕組みでそのまま使える。
- 人物の一括固定（`PERSON_FIELDS`）に年齢の表れ・髪質・前髪を追加（ONのときだけ固定）。衣装3案（`WARDROBE_FIELDS`）に衣装の細部・素材を追加（ONのときだけ衣装に合わせて作り直す）。
- 部分の引き直し：「服だけ着せ替え」に細部・素材、「髪だけ変える」に髪質・前髪、「表情・構図だけ」に視線・頭の向きを含めた。

## 2. 互換性（保存データを変えない）

- **以前の保存・共有の見え方は変わらない**：増築前のコードで作った180通りの状態（既定・詳細ON・禁断・コスプレ・獣人・固定・手動・辞書設定など）の5形式の出力を `tests/fixtures/legacy-2026.10.12.json.gz` に記録し、増築後のコードで読み込んで出力が完全に一致することを `tests/legacy-compat.test.ts` で確かめている（24件は全文、残りは SHA-256）。
- 旧データを読み込むと、新しい7項目は「なし」・スイッチOFFで補う。古い共有URL（`v=2`）は、旧モジュールの値をそのまま、新しいモジュールはOFFで復元する。
- 共有URL：新しいモジュールのフラグは既存のフラグ列の後ろに足した。7項目が「なし」かつ未固定なら、項目を符号に書かない（増築前と同じ長さ）。
- 新しい設定 `pixaiProfile`（`sdxl`／`dit`）・`novelaiProfile`（`v4`／`v5`）は、既定値が従来の出力。知らない値は既定に戻す。
- 新しい保存キーは `bpg:v1:dictSeen`（辞書の更新のお知らせを確認した版）だけ。既存のキーの消去・初期化はしない。
- `DATA_VERSION` を `2026.10.13` に上げた。シードの文字列に版が入るため、同じシードでも増築前とは別の結果になる（増築前から仕様どおり）。

## 3. 辞書の更新と抽選から除外の設定

- 既存の項目に足した候補には `since: '2026.10.13'` を付けた。辞書・抽選設定の除外はID単位なので、新しい候補は除外の設定がある項目でも抽選対象になる。
- 除外の設定を書き換えると「利用者が選んでいない変更」になるため、設定は変えず、次の3つで知らせて選べるようにした。
  1. 起動時：除外の設定がある項目に新しい候補が足されていれば、錬成画面にお知らせ（項目名と件数）。「確認する」で辞書・抽選設定へ、「このままでよい」で閉じる。確認した版は `bpg:v1:dictSeen` に記録し、同じ版では二度出さない。除外の設定がない人には出さない。
  2. 辞書・抽選設定の一覧：「この版で追加した候補」の欄（件数・うち除外中）と、「今回の追加分をすべて除外」「すべて抽選対象に戻す」。各項目に「新 N」の印。
  3. 各項目の候補一覧：「新規」の表示切り替え、「新」の印、その項目の追加分だけの一括除外・戻す。
- 一括の操作は、追加分のIDだけを足し引きする（元から除外していた候補はそのまま）。

## 4. プロンプトの出力

- **視線**：視線を指定すると、視線を決めないポーズの `looking at viewer` などと、表情に含まれる `looking away` などを外し、視線の項目のタグだけを出す（`POSE_GAZE_WORDS`／`EXPR_GAZE_WORDS`）。視線を決めるポーズ（`gazeFit`）は、合う視線だけを許し、ポーズの語を残す。
- 年齢の表れは顔のタグ、髪質・前髪は髪のタグ、素材・細部は衣装のタグの後ろに置く。自然文・日本語にもそれぞれの文を足す（「細部：…」など）。
- **PixAI**：「SDXL系（タグ）」は従来どおり。「Tsubaki等（自然文）」は自然な英文を出す（強調・品質タグは付けず、ネガティブはタグのまま）。Tsubaki は PixAI の DiT 系のモデルで、2026年7月の発表では Tsubaki.2 が「長く構造化したプロンプトに従いやすい」とされている（[PixAI のプレスリリース](https://kdhnews.com/online_features/press_releases/pixai-strengthens-anime-ai-creation-with-tsubaki-2-built-for-multi-character-scenes-and-visual/article_fc7c23ad-7621-5eb8-a51d-fe63414bd997.html)）。自然文とタグのどちらが良いかは公式に明記がなく、**実機での比較はしていない**。
- **NovelAI**：「V4（従来）」は従来どおり先頭に `best quality, very aesthetic, absurdres`。「V4.5・V5」は `very aesthetic, masterpiece, no text` を末尾に付ける。NovelAI の案内（[Add Quality Tags Toggle](https://docs.novelai.net/en/image/qualitytags)、2026-10-22 に確認）では、V5 の標準がこの3語で末尾、V4.5 Full は `location, very aesthetic, masterpiece, no text`。`location` は背景の指定と重なるため付けていない。なお同じ案内では V4 も品質タグを末尾に付けるが、V4 の出力は旧データの見え方を保つため変えていない。NovelAI 側の「Add Quality Tags」がONなら、アプリの品質タグはOFFにするよう画面で案内している。
- 自由入力の注意を増やした：視線を指定しているのに視線のタグを足す・目を閉じる視線と開いた目・年齢の語・肌や坊主など、既に決めた項目と食い違う語。

## 5. 抽選エンジンの変更

- hard 制約を22本追加（`src/advisor/hard.ts` の「2026-10 増築」の節と `light_indoor_only`）。OFF・「なし」の間はどれも成立したまま。既存の「閉じた目とこちらを見る視線」（`eyes_gaze`）は、視線を指定したときは視線の項目で判定するようにした（視線が「なし」なら従来どおり）。
- soft の重み：年齢の表れの「なし」の出やすさを年齢層ごとに（18〜24:1／25〜34:3／35〜44:4／45〜59:3／60〜:2 の比で「なし」を重く）、表情と視線・頭の向きの相性、髪型と髪質、世界観と素材、衣装と細部の相性。
- 抽選の先読み（`leavesRoom`）を広げた：候補が条件（`requires`）で名指しする項目がまだ引かれていなければ、その項目に両立する候補が残るかを確かめてから選ぶ（例：美形タイプ「ウルフヘアの気だるさ」は髪型・髪の長さ、「若き〜」は年齢層）。あわせて、髪の長さ→髪型、ポーズ→持ち物、特徴→獣人の種族を常に先読みする。固定した前髪・ごま塩のひげ・本を見る視線などと食い違う候補を先に選んで、後の項目が「元の値のまま」になる行き詰まりを防ぐ。
- 既存の不具合の修正：獣人ONで「尖った耳」の特徴を先に引くと、獣人の種族が引けずに元の値で止まることがあった（5,400回で20回）。上の先読みで0回にした。
- 卓上灯・天窓・スポットライトの並びは屋内だけ（`light_indoor_only`）。袖をまくるポーズは袖のある服だけ（`pose_sleeves`）。

## 9. 未確認・既知の制限

- **画像生成での確認はしていない**（PixAI・NovelAI の実機）。年齢の表れの強さ、視線と頭の向き、衣装の小さな細部は、モデルによって無視・誇張されることがある。「Tsubaki等（自然文）」「V4.5・V5」の出力も、各サービスで実際に生成しての確認はまだ。
- **iPhone の Safari 実機では確認していない**。Chromium の 320／375／390px で確かめた。
- テーマ25件のうち5件は「要調整」（同じ項目に2つの候補、ポーズと持ち物の手の数など）。EXPANSION-AUDIT.md §7。
- 保留6件・不採用3件は、画像での確認や関連する辞書（自転車・救急隊の制服など）の追加が必要（EXPANSION-AUDIT.md §5）。
- サービスワーカーのキャッシュ名（`bpg-v2`）は変えていない。HTML はネットワーク優先で、ビルドの資産はファイル名にハッシュが付くため、更新は次にオンラインで開いたときに届く（従来どおり）。
